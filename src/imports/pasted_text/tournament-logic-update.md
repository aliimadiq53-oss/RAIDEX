# تعديل نظام AL AFANDI — بطولة الكر والفر فقط

أريد تعديل النظام الحالي مع **الحفاظ الكامل على الـUI والـDesign System الحالي**.

لا تغيّر:

* الهوية البصرية.
* الألوان.
* الخطوط.
* أسلوب التصميم.
* الـComponents.
* شكل الموقع العام.

المطلوب هو تعديل **منطق إدارة البطولات فقط**.

---

# 1. حذف البطولات الحالية

احذف جميع البطولات التجريبية والحالية التي تم إنشاؤها داخل النظام.

لا أريد حالياً وجود أنواع بطولات متعددة.

ولا أريد:

* زر إضافة نوع بطولة.
* Tournament Builder.
* Ruleset Library متعددة.
* بطولات تجريبية.
* اختيار نوع البطولة عند الإنشاء.

حالياً النظام يعتمد بطولة واحدة فقط:

# بطولة الكر والفر

لكن لا تجعلها سجلاً واحداً يتم مسحه وإعادة استخدامه.

يجب أن تعمل بنظام:

# Tournament Template + Tournament Editions

---

# 2. قالب بطولة الكر والفر

أنشئ قالباً أساسياً دائماً باسم:

# بطولة الكر والفر

هذا القالب يحتوي على جميع إعدادات وقوانين بطولة الكر والفر المعتمدة في المشروع.

القالب يحتفظ بـ:

* اسم البطولة.
* نوع البطولة.
* نظام البطولة.
* عدد الجولات.
* إعدادات الجولات.
* نظام الوقت.
* نظام النقاط.
* قواعد التصنيف.
* الأخطاء المعرفة مسبقاً.
* العقوبات.
* قواعد الاستبعاد.
* إعدادات الحكم.
* آلية إرسال النتائج.
* آلية اعتماد النتائج.
* إعدادات النتائج المباشرة.
* إعدادات شاشة العرض.

هذا القالب هو المرجع الذي يتم منه إنشاء كل بطولة جديدة.

---

# 3. لا تنقل البيانات التشغيلية القديمة

القالب لا يحتوي على:

* المشاركين السابقين.
* أرقام المشاركة السابقة.
* النتائج السابقة.
* أوقات اللاعبين.
* أخطاء اللاعبين.
* نقاط اللاعبين.
* الترتيب السابق.
* الاستبعادات السابقة.
* سجل اعتماد بطولة سابقة.

هذه البيانات تخص كل نسخة بطولة بشكل مستقل.

---

# 4. Dashboard عندما لا توجد بطولة

إذا لم توجد بطولة حالية أو قادمة، اعرض في Dashboard:

# بطولة الكر والفر

**قالب البطولة جاهز**

4 جولات

القوانين والإعدادات جاهزة

ثم زر رئيسي:

# بدء بطولة جديدة

لا تستخدم:

**إنشاء بطولة جديدة**

ولا تطلب اختيار نوع البطولة.

لأن النوع الوحيد حالياً هو:

**الكر والفر**

---

# 5. بدء بطولة جديدة

عند الضغط على:

# بدء بطولة جديدة

افتح نافذة بسيطة جداً.

المطلوب الأساسي من Admin:

# تاريخ البطولة

مثلاً:

`15 / 09 / 2026`

ثم زر:

# إنشاء البطولة

لا تطلب منه إعادة إدخال:

* القوانين.
* النقاط.
* الأخطاء.
* الجولات.
* نظام الوقت.
* قواعد الاستبعاد.

كلها تأتي تلقائياً من قالب الكر والفر.

---

# 6. معلومات اختيارية

يمكن السماح أيضاً بإدخال أو تعديل:

* اسم النسخة.
* المكان.
* وقت البداية.
* صورة/Banner البطولة.
* وصف مختصر.

لكن اجعل:

# التاريخ

هو الحقل الأساسي المطلوب لإنشاء نسخة جديدة.

---

# 7. إنشاء Tournament Edition

إذا اختار Admin مثلاً:

**15 سبتمبر 2026**

ينشئ النظام:

# بطولة الكر والفر

## 15 سبتمبر 2026

وتكون هذه:

**Tournament Edition مستقلة**

ولها ID مستقل.

---

عند إنشاء البطولة الجديدة:

---

# 9. تعديل القالب مستقبلاً

إذا تم تعديل قالب الكر والفر مستقبلاً:

لا تغير البطولات السابقة.

مثال:

بطولة أغسطس استخدمت:

**Rules Version 1**

ثم تم تعديل القالب.

بطولة سبتمبر الجديدة تستخدم:

**Rules Version 2**

لكن بطولة أغسطس تبقى بالقواعد التي كانت مستخدمة وقتها.

---

# 10. حالة البطولة الجديدة

بعد إنشاء نسخة البطولة لا تبدأ المنافسة مباشرة.

الحالة تكون:

# لم تبدأ

ويستطيع Admin تجهيزها قبل يوم البطولة.

مثل:

* إضافة المشاركين.
* تحديد أرقام المشاركة.
* تعيين الحكام.
* مراجعة الجولات.
* مراجعة القوانين.
* مراجعة الأخطاء.

---

# 11. المشاركون

كل Tournament Edition تبدأ:

# بدون مشاركين.

يستطيع Admin أو Data Entry إضافة اللاعبين من قاعدة اللاعبين الموجودة.

كل لاعب لديه:

**Player Profile دائم**

لكن مشاركته مرتبطة بالبطولة الحالية.

---

# 12. رقم المشاركة

رقم المشاركة:

# خاص بنسخة البطولة الحالية.

مثال:

علي عماد كاظم

بطولة الكر والفر — أغسطس:

**14**

بطولة الكر والفر — سبتمبر:

**27**

بطولة الكر والفر — أكتوبر:

**8**

وكلها مرتبطة بنفس Player Profile.

---

# 13. منع تكرار رقم المشاركة

لا تسمح بوجود مشاركين يحملان نفس Competition Number داخل نفس Tournament Edition.

إذا كان الرقم مستخدماً:

**رقم المشاركة مستخدم بالفعل في هذه البطولة**

لكن يمكن استخدام نفس الرقم في بطولة أخرى.

---

# 14. الحكام

كل نسخة بطولة تبدأ بدون افتراض أن نفس الحكام السابقين سيشاركون.

Admin يختار الحكام من حسابات الحكام الموجودة.

مثلاً:

# تعيين الحكام

ثم اختيار:

الحكم الأول.

الحكم الثاني.

الحكم الثالث.

ويمكن تحديد الجولات المخصصة لكل حكم.

---

# 15. الجولات

وفق متطلبات بطولة الكر والفر المقدمة للمشروع، القالب الحالي يحتوي على:

# 4 جولات

* الجولة الأولى.
* الجولة الثانية.
* الجولة الثالثة.
* الجولة الرابعة.

لكل جولة حالة:

**لم تبدأ**

**جارية**

**مكتملة**

---

# 16. قواعد النقاط الحالية

استخدم قواعد الكر والفر المقدمة للمشروع فقط.

## صفر أخطاء

يتم ترتيب أصحاب صفر أخطاء حسب الوقت.

### المركز الأول

**4 نقاط**

### المركز الثاني

**3 نقاط**

### المركز الثالث

**2 نقطة**

---

# 17. صفر أخطاء خارج أول ثلاثة

وفق المتطلبات المقدمة:

اللاعب الذي يكون:

**بدون أخطاء + ضمن حالة الوقت الاعتيادي المحددة**

وخارج المراكز الثلاثة الأولى:

**1 نقطة**

---

# 18. خطأ واحد

الفئة المحددة من أصحاب:

**خطأ واحد + وقت تنافسي**

تحصل على:

**0.5 نقطة**

وفق شروط وترتيب البطولة المحددة.

---

# 19. صفر نقطة

الحالات المذكورة التي تحصل على:

# 0

تشمل:

**خطأ واحد + وقت اعتيادي**

و:

**خطآن أو أكثر**

و:

**المستبعد** وفق متطلبات النظام الحالية.

---

# 20. لا تخترع قواعد غير محددة

مهم جداً:

لا تفترض من عندك:

* الحد الزمني للوقت التنافسي.
* الحد الزمني للوقت الاعتيادي.
* طريقة جمع نقاط الجولات الأربع.
* Tie Break النهائي.
* أي قانون عالمي إضافي.

إذا كانت هناك قاعدة غير محددة في متطلبات المشروع، اتركها كإعداد يحتاج إلى تحديد.

---

# 21. زر بدء البطولة الفعلي

بعد تجهيز المشاركين والحكام، يظهر لـAdmin:

# بدء البطولة

هذا مختلف عن:

**بدء بطولة جديدة**

الفرق:

**بدء بطولة جديدة**
= إنشاء Tournament Edition من القالب.

**بدء البطولة**
= تفعيل المنافسة الفعلية للنسخة التي تم تجهيزها.

---

# 22. تأكيد بدء البطولة

عند الضغط:

# بدء البطولة

اعرض Confirmation Modal:

**بدء بطولة الكر والفر؟**

بعد البدء سيتم:

* تفعيل البطولة.
* تفعيل واجهات الحكام.
* السماح بإدخال النتائج.
* تفعيل الجولات.
* استقبال نتائج المشاركين.

الأزرار:

**رجوع**

**تأكيد بدء البطولة**

---

# 23. عند بدء البطولة

تتغير الحالة:

**لم تبدأ → جارية الآن**

ويتم:

* تفعيل Judge Portal.
* السماح للحكام باختيار البطولة.
* تفعيل البحث عن المشاركين.
* استقبال الوقت والأخطاء.
* إرسال النتائج إلى Admin.
* تفعيل اعتماد النتائج.
* تفعيل Live Control.

---

# 24. واجهة الحكم

عند دخول الحكم:

لا تعرض Admin Dashboard.

لا تعرض Statistics.

لا تعرض قائمة لاعبين.

أول شيء:

# اختر البطولة النشطة

إذا كانت لديه بطولة واحدة نشطة فقط:

يمكن اختيارها تلقائياً.

---

# 25. اختيار البطولة مهم

البحث عن اللاعب لا يعمل قبل تحديد Tournament Edition.

لأن:

# Competition Number is Tournament-Specific

أي أن رقم المشاركة يختلف من بطولة إلى أخرى.

---

# 26. شاشة الحكم بعد اختيار البطولة

اعرض أعلى الشاشة بشكل ثابت:

**بطولة الكر والفر — 15 سبتمبر 2026**

**الجولة الثانية**

**اسم الحكم**

ثم حقل كبير فقط:

# رقم المشاركة

لا يوجد زر:

**بحث**

الحكم يكتب مثلاً:

`14`

والنظام يبحث تلقائياً.

---

# 27. البحث التلقائي

البحث يكون باستخدام:

**Tournament Edition ID + Competition Number**

ولا يبحث في البطولات السابقة.

مثال:

رقم 14 في بطولة أغسطس يمكن أن يكون علي.

ورقم 14 في بطولة سبتمبر يمكن أن يكون أحمد.

وهذا طبيعي.

---

# 28. ظهور اللاعب

بعد كتابة الرقم يظهر تلقائياً:

**اسم اللاعب**

**رقم المشاركة**

ثم:

# الوقت

ثم:

# الأخطاء

ثم:

# إرسال النتيجة

ولا تعرض للحكم بيانات شخصية أو إدارية غير ضرورية.

---

# 29. الأخطاء

الحكم لا يكتب أسماء الأخطاء يدوياً.

يعرض النظام الأخطاء المعرفة مسبقاً في Snapshot الخاص ببطولة الكر والفر الحالية.

الحكم يختار الخطأ الذي حدث.

ويمكن تحديد العدد عند الحاجة.

---

# 30. إرسال النتيجة

عند الضغط:

# إرسال النتيجة

لا تظهر النتيجة مباشرة للجمهور.

تكون:

# بانتظار الاعتماد

وتصل إلى Admin.

بعد الإرسال:

* امسح اللاعب السابق.
* امسح الوقت.
* امسح الأخطاء.
* ضع Focus تلقائياً على رقم المشاركة.

حتى يستطيع الحكم إدخال اللاعب التالي بسرعة.

---

# 31. اعتماد النتائج

Admin لديه:

# اعتماد النتائج

ويرى:

* رقم المشاركة.
* اسم اللاعب.
* الجولة.
* الحكم.
* الوقت.
* الأخطاء.
* النقاط المحسوبة حسب القواعد المحددة.
* وقت إرسال النتيجة.

الإجراءات:

**اعتماد**

**تعديل**

**رفض**

---

# 32. النتيجة لا تظهر قبل موافقة Admin

هذه قاعدة إلزامية:

Judge Result

↓

Pending Approval

↓

Admin Review

↓

Approved

↓

Published

أي نتيجة لم يعتمدها Admin:

# لا تظهر في الموقع الرسمي.

---

# 33. النتائج المباشرة في الموقع الرسمي

الموقع الرسمي يحتوي على:

# النتائج المباشرة

لكن يعرض فقط:

**النتائج المعتمدة والمسموح بنشرها**

ولا يعرض النتائج بمجرد إرسال الحكم لها.

صفحة النتائج تحدث تلقائياً بدون Refresh عند نشر نتيجة جديدة.

---

# 34. Live Control

Admin لديه:

# التحكم بالعرض المباشر

النتائج المعتمدة تظهر له.

يستطيع اختيار نتيجة ثم:

# عرض الآن

وهذه تتحكم بشاشة العرض الخاصة بالبطولة.

لا تجعل Judge Result يتحكم مباشرة بالشاشة.

---

# 35. الفصل بين الموقع وشاشة البطولة

هناك:

## Public Live Results

داخل الموقع الرسمي للجمهور.

وهناك:

## Venue Live Display

للشاشة الكبيرة داخل البطولة.

وهناك:

## Admin Live Control

للتحكم بما يظهر على شاشة البطولة.

هذه ثلاث واجهات مختلفة.

---

# 36. الاستبعاد والحظر

في واجهة الحكم، تحت إرسال النتيجة:

## إجراءات إضافية

**استبعاد اللاعب**

**حظر اللاعب**

الاستبعاد مرتبط:

**بمشاركة اللاعب في البطولة/الجولة**

الحظر مرتبط:

**بـPlayer Profile**

ولا يستطيع إزالة الحظر إلا:

# Admin المخول.

---

# 37. زر إلغاء البطولة

Admin لديه أيضاً:

# إلغاء البطولة

عند الضغط:

اعرض:

**هل أنت متأكد من إلغاء بطولة الكر والفر؟**

واطلب:

# سبب الإلغاء

ثم:

**رجوع**

**تأكيد الإلغاء**

---

# 38. إلغاء بطولة بدأت

إذا كانت البطولة تحتوي على نتائج بالفعل:

اعرض Warning:

**تحتوي هذه البطولة على بيانات ونتائج مسجلة. سيؤدي الإلغاء إلى إيقاف استقبال النتائج الجديدة، ولن يتم حذف البيانات المسجلة سابقاً.**

بعد التأكيد:

الحالة:

# ملغاة

* السبب.

في Audit Log.

# 39. إنهاء البطولة

# قالب بطولة الكر والفر

**القالب جاهز لبطولة جديدة**

# 45. Architecture

حالياً واجهة المستخدم تحتوي فقط على:

# بطولة الكر والفر

لكن لا تبنِ Backend بطريقة تمنع إضافة أنواع بطولات أخرى مستقبلاً.

Architecture يجب أن تبقى:

# Multi-Tournament Ready

لكن UI الحالية:

# Karr & Farr Only

لا تظهر للمستخدم حالياً:

* أنواع بطولات أخرى.
* Tournament Builder.
* Add Tournament Type.
* Ruleset Library متعددة.

# 47. القاعدة النهائية

لا تعامل بطولة الكر والفر كسجل واحد يتم مسحه وإعادة تشغيله.

بل:

**قالب الكر والفر**
→ بطولة أغسطس
→ أرشيف

**نفس القالب**
→ بطولة سبتمبر
→ أرشيف

**نفس القالب**
→ بطولة أكتوبر
→ أرشيف

وهكذا.

كل نسخة مستقلة تماماً في:

التاريخ.

المشاركين.

أرقام المشاركة.

الحكام.

النتائج.

الأوقات.

الأخطاء.

النقاط.

التعديلات.

الاعتمادات.

الأرشيف.
