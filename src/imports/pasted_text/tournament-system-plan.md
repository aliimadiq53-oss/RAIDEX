# 7. يوزرات الحكام

الحكم يجب أن يكون User داخل النظام.

لكن لا يدخل إلى Admin Dashboard الكامل.

عند إنشاء حساب حكم:

يتم تحديد:

- اسم الحكم
- Username
- Password
- البطولات المسموح له بالدخول إليها
- الجولات المسندة إليه
- الصلاحيات

يمكن أن يكون الحكم مستخدماً في أكثر من بطولة.

---

# 8. دخول الحكم

الحكم يستطيع استخدام رابط Login خاص أو نفس Login الرئيسي.

بعد تسجيل الدخول، النظام يتعرف على Role:

**Judge**

ويفتح مباشرة:

**واجهة الحكم**

ولا يظهر له Admin Dashboard.

**اختر البطولة**

# 39. نقاط الكر والفر الحالية

حسب المتطلبات المقدمة:

أصحاب:

**0 أخطاء**

يتم ترتيبهم حسب الأقل وقتاً.

المركز الأول:

**4 نقاط**

المركز الثاني:

**3 نقاط**

المركز الثالث:

**2 نقطة**

باقي أصحاب صفر أخطاء المستوفين لشرط الوقت:

**1 نقطة**

الفئة المحددة من أصحاب خطأ واحد مع الوقت التنافسي:

**0.5 نقطة**

خطأ واحد خارج الفئة المستحقة:

**0**

خطآن أو أكثر:

**0**

هذه القواعد تخص Ruleset الكر والفر الحالي ولا تطبق على جميع أنواع البطولات.

# 70. قاعدة أخيرة مهمة

لا تعيد اختراع الـUI.

**وسع النظام باستخدام الـDesign System الحالي فقط.**

أي شاشة جديدة يجب أن تبدو وكأنها كانت جزءاً من المشروع منذ البداية.

حافظ على:

Clean UI

Contemporary Arabic Design

AL AFANDI Identity

Generous Spacing

Minimal Cards

Strong Typography

Clear Hierarchy

Fast Operational UX

ولا تضحي بسهولة الاستخدام من أجل الزخرفة.

الموقع العام يبقى:

**Cinematic + Editorial + Brand Focused**

أما النظام الداخلي:

**Clean + Fast + Data Focused**

أما شاشة العرض المباشر:

**Bold + Minimal + Extremely Readable + Premium**

وجميعها يجب أن تبدو أجزاءً من نفس عالم:

# AL AFANDI
